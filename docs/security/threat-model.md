# 위협 모델

두리가 무엇을 지키고, 무엇을 막고, **무엇은 막지 못하는지**를 솔직하게 적어요. 기능이 붙을 때마다 갱신해요.

> 현재 단계: **M0~M1 (개발 초기)**. 아래 표의 "상태" 열은 지금 실제로 구현된 것과 계획만 있는 것을 구분해요. 계획을 구현된 것처럼 말하지 않아요.

## 1. 지키는 것

| 자산 | 설명 |
|---|---|
| 사용자의 돈 | 결제, 예약 확정, 수수료가 생기는 취소 |
| 사용자의 관계 | 메시지·메일·글을 사용자 이름으로 보내는 일 |
| 계정과 로그인 상태 | 브라우저에 로그인된 서비스, AI 구독 |
| 대화와 기록 | 부탁 내용, 한 일, 화면 캡처, 허락 내역 |
| 사용자 PC | 파일, 설치된 프로그램 |

## 2. 신뢰 경계

```
[사용자] ─ 폰(M6) ─ 중계 서버(M6, 신뢰하지 않음) ─┐
                                                  ▼
[사용자 PC] ── 두리 앱·본체 dool2d (신뢰) ── 로컬 API 127.0.0.1 + 토큰
                  │
                  ├── 에이전트(Claude Code / Codex): 반쯤 신뢰
                  │     └ AI 판단은 틀릴 수 있고, 웹페이지 내용에 속을 수 있다
                  ├── 두리 도구(MCP) → 승인 게이트 → 브라우저·PC 제어
                  └── 웹페이지·외부 앱의 내용: 신뢰하지 않음
```

핵심 가정: **AI 에이전트를 믿지 않아요.** AI는 실수하고, 웹페이지에 숨은 지시(프롬프트 주입)에 속을 수 있어요. 그래서 안전은 AI의 판단이 아니라 코드(도구 제한과 승인 게이트)로 지켜요.

## 3. 위협과 대응

| # | 위협 | 대응 | 상태 |
|---|---|---|---|
| T1 | AI가 셸·파일·웹 기능으로 게이트를 우회 | 에이전트 내장 도구를 끄고 두리 도구만 허용. 시작 시 도구 목록 검사, 실행 중 위험 항목 감지 시 중단 ([ADR 0003](../decisions/0003-dool2-tools-only.md)) | ✅ 구현 |
| T2 | 웹페이지의 프롬프트 주입으로 결제·연락 시도 | 돈 내기·연락하기 등급은 사용자 허락 없이는 실행 불가. 등급은 AI가 아니라 두리가 판단 | 🗓 M3 |
| T3 | 범용 클릭으로 결제 버튼을 누름 | 클릭 직전 요소 글자·URL·스킬 표시로 위험 판단, 하나라도 위험하면 위험. 결제 도메인 요청 차단 | 🗓 M3 |
| T4 | 다른 프로그램이나 웹페이지가 로컬 API 호출 | 127.0.0.1에만 열고, 실행마다 새로 만든 토큰 필요(시간 일정 비교) | ✅ 구현 |
| T5 | 다른 프로그램이 두리 도구(MCP)를 직접 호출 | 에이전트 실행 시 일회용 토큰을 넘기고 본체가 확인 | 🗓 M2 |
| T6 | Claude 구독 자격 증명 유출 | 두리는 Claude 로그인 정보·토큰을 읽거나 저장하지 않음 ([ADR 0002](../decisions/0002-official-agent-binaries.md)) | ✅ 구현 |
| T7 | 대화 기록 유출 | 기록은 사용자 PC의 SQLite에만 저장. 원격 전송 없음 | ✅ 구현 |
| T8 | 캡차·본인인증 자동 우회로 계정 정지 | 우회하지 않고 사람에게 화면을 넘김. 우회 코드·스킬은 받지 않음 | 🗓 M2 |
| T9 | 중계 서버가 내용을 엿보거나 바꿈 | 종단 간 암호화, 허락은 PC가 폰 공개키로 직접 검증 | 🗓 M6 |
| T10 | 허락 화면 위조(보이는 내용과 서명 내용이 다름) | 서명 대상은 PC가 만든 요청 해시. 돈 내기는 네이티브 앱 서명을 우선 | 🗓 M6 |
| T11 | 변조된 설치 파일·업데이트 | GitHub Actions에서만 빌드, 코드 서명·공증, 빌드 출처 증명, 서명된 업데이트만 설치 | 🗓 M5 |
| T12 | 악성 스킬 기여 | 스킬은 게이트를 끌 수 없음. 등급 표기·금지 지시 CI 검사, 메인테이너 리뷰 | 🗓 M4 |
| T13 | 의존성 공급망 공격 | 잠금 파일 고정, CI 액션 커밋 고정, 의존성 알림, Codex 버전 고정 | ✅ 일부 |

## 4. 막지 못하는 것

- **이미 악성코드에 감염된 PC.** 같은 사용자 권한으로 도는 악성코드는 두리의 메모리, 기록, 브라우저를 볼 수 있어요.
- **사용자가 내용을 확인하지 않고 허락한 경우.** 두리는 허락 화면에 무엇을·어디서·얼마인지·취소 조건을 또박또박 보여 주지만, 최종 판단은 사용자 몫이에요.
- **AI 회사 쪽 문제.** Claude Code·Codex 서비스 자체의 장애나 보안 사고.
- **서비스 약관.** 자동화를 금지하는 서비스도 있어요. 두리는 사람 속도로 사용자 대신 조작하지만, 약관 판단은 서비스마다 달라요. 스킬에 알려진 제한을 적어요.

## 5. 고정된 보안 테스트

다음 테스트는 지우거나 약하게 만들 수 없어요. 바꾸려면 이 문서를 함께 고치고 이유를 적어야 해요.

- 에이전트가 두리 도구 밖의 도구를 알리면 실행이 멈춘다 (`packages/agent-claude`, `packages/agent-codex`)
- 토큰 없이 로컬 API를 부르면 거절된다 (`apps/daemon`)
- (M3) 허락 없이 돈 내기·연락하기 도구가 실행되면 테스트가 실패한다 (`packages/gate`)

취약점을 찾으셨다면 [보안 정책](../../SECURITY.md)에 따라 비공개로 알려 주세요.
