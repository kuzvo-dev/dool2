# 0021. 연결하기: 자동 로그인이 멈추면 두리가 대화에서 이어받고, 하는 일은 늘 대화에 보인다

- 상태: 채택
- 날짜: 2026-11-18

## 배경

연결하기(대신 로그인)는 본체가 정해 둔 순서로 했어요: 로그인 링크 찾기 → 칸 채우기 → 버튼 → 화면 글로 결과 보기.
빠르고(10초 안팎) AI 사용량을 쓰지 않지만, 화면이 그 순서와 조금만 달라도 "로그인 칸을 찾지 못했어요"로 끝났어요.

- 실제 사이트 점검(2026-11-18, 연결 카드 74곳, 넣거나 누르지 않고 칸만 찾기): 찾음 60곳, 못 찾음 9곳, 사람 차례 2곳, 열기 실패 3곳.
  다섯 곳 중 한 곳은 아이디·비밀번호를 넣기도 전에 실패해요.
- 연결은 뒤에서 했고 글자 단계만 보였어요. 사용자는 지금 무엇을 하는지, 왜 멈췄는지 볼 수 없었어요.
- 사용자가 써 보고 한 말: "서비스 연결이 한 번에 된 적이 없다", "채팅에서 해야 지금 뭐 하는지 알 수 있다".

## 결정

1. **먼저 자동 로그인, 멈추면 두리가 이어받는다.** 자동 로그인이 화면을 못 알아봐 멈춘 경우(`unknown`: 로그인 칸·결과를 모름)에는
   실패 카드로 끝내지 않고, 본체가 메인 대화에 앱 알림을 보내 두리(AI)가 그 탭을 이어받게 한다. 두리는 화면을 읽고 맞춰 가며 로그인한다.
   아이디·비밀번호가 틀림(`wrong`), 사람 차례(`human`: 로봇 확인·본인인증)는 이어받지 않는다. 전처럼 다시 넣기·화면 넘기기로 간다.
2. **서비스마다 10분에 한 번만.** 그래도 안 되면 사용자가 [화면 보며 직접]으로 마친다 (마치면 지켜보던 쪽이 알아서 연결로 표시).
3. **계정은 여전히 금고에서 칸으로만.** 두리는 `browser_login`으로 칸만 알려 주고 값은 본체가 확장에 직접 넘긴다 ([0011](0011-login-vault.md)).
   이어받은 탭에 한해, 로그인 화면이 그 서비스 사이트의 다른 주소(`login.사이트`)여도 연결할 때 넣은 계정을 쓴다.
   다른 사이트(간편 로그인 공급자 등)로 넘어간 화면에는 넣지 않는다. 금고는 같은 사이트에 계정이 여럿이면 가장 나중에 넣은 것을 준다.
4. **하는 일은 대화에 보인다.** 연결 카드에는 로그인하는 화면이 작게 실시간으로 보이고(누르면 크게 열어 직접 할 수 있다),
   이어받은 뒤에는 대화의 일하는 화면·단계로 보인다. 서비스 도구로 일할 때도 같은 화면이 뜬다 (본체가 탭을 여는 순간 알린다).
5. **연결이 끝나면 대화로.** 화면에서 직접 마쳤든 두리가 마쳤든 대화로 돌아오고, 미뤄 둔 부탁(연결하면 바로 시작)을 이어서 보낸다.

## 이유

- 사이트 81곳의 로그인 화면을 규칙으로 다 맞추는 것은 끝이 없어요. 사이트가 바뀔 때마다 다시 어긋나요.
  규칙은 빠른 길로 남기고, 어긋났을 때는 화면을 읽을 수 있는 쪽이 이어받는 편이 한 번에 되는 비율을 올려요.
- 처음부터 AI로 하면 느리고(30~60초) 구독 사용량을 써요. 잘 되는 곳은 지금처럼 10초 안에 끝나야 해요.
- 무엇을 하는지 보여야 믿고 기다릴 수 있어요. 안 보이는 뒤쪽 작업은 실패했을 때 까닭도 알 수 없어요.

## 따져 본 것

- **처음부터 AI로 로그인**: 가장 잘 맞추지만 매번 느리고 사용량을 써요. 고르지 않았어요.
- **규칙을 더 늘리기**: 지금까지 해 온 방식. 사이트마다 고치는 일이 끝나지 않아 고르지 않았어요 (빠른 길로는 유지).
- **이어받은 탭에서 금고 주소 맞추기를 느슨하게**: 같은 사이트의 다른 주소까지만 허용했어요. 그보다 넓히면 피싱 화면에 넣을 위험이 생겨요.

## 남은 일

- 실제 계정으로 서비스마다 "한 번에 연결되는 비율"을 재서 표로 남기기 (`scripts/connect-test.mjs`).
- 이어받은 결과(됐음·사람에게 넘김·못 함)를 서비스별로 기록해, 자주 이어받는 곳은 자동 로그인 규칙을 고치기.
