# 0018. 서비스는 커넥터(서비스별 도구)로 붙인다

- 상태: 채택
- 날짜: 2026-11-17
- 고치는 결정: [0014](0014-connect-cards.md)의 "절차 문서 `SKILL.md`" 부분 (연결 카드는 그대로)

## 배경

지금까지 두리는 어느 서비스든 범용 브라우저 도구(열기·읽기·누르기)로 일했어요. 서비스별 요령은 `SKILL.md`에 글로 적어 AI가 읽게 했어요. 실제로 돌려 보니:

- **느리고 비싸요.** 캐치테이블에서 검색부터 예약금 안내까지 64초, 화면 읽기·누르기 20번 넘게 걸렸어요. 매번 화면 전체를 AI가 읽어요.
- **틀릴 틈이 많아요.** 목록 재활용, 덮인 버튼, 결제 화면의 '다음'처럼, 한 단계만 헷갈려도 엉뚱한 곳으로 가요.
- **글은 강제가 안 돼요.** "예약금 화면에서 멈춘다"고 적어도, 지키는 건 AI의 판단이에요.
- 한 사이트를 돌려 보며 고친 것이 다른 사이트에서도 맞는지 확인할 방법이 없어요.

## 결정

### 1. 서비스 하나 = 커넥터 하나

`skills/<id>/` 폴더에 연결 카드(`connect.json`)와 함께 **커넥터 `tools.json`** 을 둬요. 커넥터는 그 서비스에서 할 수 있는 일을 **타입 있는 도구**로 적어요.

```
skills/catchtable/
  connect.json   연결 화면 카드 (ADR 0014, 그대로)
  tools.json     도구: 이름·설명·입력·출력·등급 + 실행 순서(steps)
```

도구 하나는 이렇게 생겼어요.

- `name` `title` `description`: AI가 보는 안내. **언제 쓰는지, 무엇을 돌려주는지, 다음에 무엇을 하면 되는지**를 적어요. `SKILL.md`에 있던 요령은 여기와 입력 칸 설명으로 옮기고, 나머지(주소·화면 순서)는 steps 안에 숨겨요.
- `input`: 입력 칸(JSON 스키마의 작은 부분집합: 글·수·참거짓·고르기, 설명·형식·범위). 필수 칸이 곧 "사용자에게 먼저 확인할 것"이에요.
- `output`: 돌려주는 모양. MCP의 `outputSchema`/`structuredContent`로 그대로 나가요.
- `tier`: 권한 등급(찾아보기·채워 두기·돈 내기·연락하기). MCP 힌트(`readOnlyHint`·`destructiveHint`·`idempotentHint`)도 여기서 만들어요.
- `login`: 로그인이 있어야 하는 도구인지.
- `examples`: 입력 예시. AI 안내에 붙고, 매일 도는 실제 사이트 시험(카나리)의 입력이 돼요.
- `steps`: 실행 순서. 정해진 동작(열기·기다리기·글자로 누르기·입력·목록 뽑기·화면이 받은 응답 읽기·승인 요청·돌려주기)만 이어 붙여요.

### 2. 확장은 고정된 엔진, 커넥터는 데이터

- 확장에는 **범용 동작만** 둬요: 화면 읽기, 누르기·입력, 그리고 이번에 더하는 **목록 뽑기(extract)**, **글자 찾기(find)**, **그 화면이 받은 응답 읽기(capture)**.
- 커넥터는 코드가 아니라 데이터(`tools.json`)라서 두리 본체가 읽어 엔진 동작으로 풀어 실행해요.
  - Chrome 웹 스토어는 확장이 밖에서 받은 코드를 실행하는 걸 금지해요. 사이트가 바뀔 때마다 확장을 다시 심사받지 않아도 돼요.
  - 커넥터가 할 수 있는 일은 엔진 동작으로 정해져요. **커넥터가 승인 게이트를 끄거나 비켜 갈 방법이 없어요.** 누르기는 지금과 같은 위험 판단(`classifyRisk`)을 거치고, 찾아보기 도구는 위험한 버튼을 아예 못 눌러요. 돈 내기·연락하기 도구는 마지막 버튼을 승인 요청으로만 끝낼 수 있어요.
  - 기여자는 JSON 하나를 고치면 되고, 레포 테스트가 형식과 안전 규칙을 검사해요.

### 3. AI에게 보이는 방식 (MCP)

- **연결한 서비스의 도구는 바로 보여요.** 예: `catchtable_search`, `catchtable_prepare_booking`. 로그인 없이 쓰는 서비스(`how: open`)의 도구도 바로 보여요.
- **나머지는 찾아서 써요.** `service_find`(서비스 찾기: 할 수 있는 일, 연결 여부, 도구와 입력 칸)와 `service_call`(찾은 도구 실행)이에요. 86개 서비스 × 서너 개 도구를 한꺼번에 내밀면 AI가 헷갈리고 매 차례 토큰이 많이 들어요.
- 연결 상태가 바뀌면 도구 목록을 새로 알려요(`tools/list_changed`). 이걸 못 받는 실행기라도 `service_call`은 늘 돼요.
- 결과는 **글 + 구조화된 데이터**로 함께 돌려줘요. 글은 짧은 표나 줄, 데이터는 `output` 모양이에요.
- 실패하면 **다음에 할 일**을 적어 돌려줘요. 사이트가 바뀌어 커넥터가 못 읽으면, 열어 둔 탭 번호와 함께 "브라우저 도구로 이어서 하세요"라고 알려요. 그 일은 기록해 두고 카나리가 다시 확인해요.

### 4. 연동 안내

- 연결이 필요한 도구를 연결 전에 부르면 실행하지 않고 **연결 안내**를 돌려줘요: 연결하면 무엇을 바로 할 수 있는지, `connect_ask`로 연결 카드를 띄우라는 것.
- 범용 브라우저로 커넥터가 있는 사이트를 열면, 첫 읽기에 "이 사이트는 두리 커넥터가 있어요: …"라고 붙여 커넥터를 쓰게 해요.
- 부탁에 맞는 서비스를 아직 연결하지 않았으면, AI는 로그인 없이 되는 도구로 먼저 찾아 주고, 예약·주문 단계에서 연결을 권해요(페르소나 지침 그대로).

### 5. `SKILL.md`는 없앤다

- 있던 두 개(캐치테이블, CJ대한통운)는 커넥터로 옮기고 지워요. `skill_find`/`skill_read`는 `service_find`가 대신해요.
- 커넥터가 아직 없는 서비스는 연결 카드만으로 범용 브라우저 도구를 써요. 짧은 요령이 꼭 필요하면 카드의 `hints`(1~3줄: 검색 주소 등)에 적어요.

### 6. 상태와 검증

- 도구마다 상태를 적어요: `검증됨(YYYY-MM-DD)`, `초안`, `막힘(사유)`.
  - 초안 도구도 실행은 돼요. 결과에 "처음 써 보는 길이라 결과를 한 번 더 확인해 주세요"가 붙어요.
  - 막힘 도구는 보이지 않아요.
- 커넥터 단위 시험: 가짜 엔진으로 steps를 끝까지 돌려 보는 테스트(레포 테스트).
- 실제 사이트 시험(카나리): 찾아보기 도구를 `examples` 입력으로 돌려 보는 스크립트. 매일 돌려 깨진 커넥터를 찾아요.

### 7. 라이선스

`tools.json`도 `skills/` 안의 데이터라 CC BY-SA 4.0이에요([ADR 0008](0008-skills-cc-by-sa.md)). 엔진·실행기 코드는 Apache-2.0이에요.

## 이유

- **빠르고 정확해요.** AI는 "무엇을"만 정하고 "어떻게"는 검증된 순서가 해요. 화면 전체를 매번 읽지 않아요.
- **안전 규칙이 코드로 지켜져요.** 등급별로 할 수 있는 엔진 동작이 정해지고, 승인 게이트는 그대로예요.
- **사이트가 바뀌어도 스토어 심사가 필요 없어요.** 엔진은 그대로 두고 데이터만 바꿔요.
- **한 사이트에만 맞추는 걸 막아요.** 카나리가 모든 커넥터를 매일 돌려요.

검토한 다른 안:

- **서비스별 TypeScript 코드**: 표현력은 크지만, 확장에 넣으면 고칠 때마다 스토어 심사를 받아야 하고, 본체에 넣으면 커넥터가 엔진 밖의 일을 할 수 있어 검토 부담이 커요. 기여 문턱도 높아요.
- **사이트 서버 API를 본체에서 직접 부르기**: 쿠키를 브라우저 밖으로 빼야 해서 하지 않아요(ADR 0006, 보안). 
- **모든 도구를 늘 보여 주기**: 도구가 300개를 넘어요. 연결한 것만 보여 주고 나머지는 찾게 했어요.
- **`SKILL.md` 유지**: 글은 강제가 안 되고, 도구 안내와 두 군데에 같은 내용을 적게 돼요.

## 결과

- 새 서비스나 수정은 `tools.json`으로 해요. 레포의 커넥터 작성 스킬(`.claude/skills/connector`)이 순서를 안내해요.
- 엔진 동작을 더하려면 확장 새 버전(스토어 심사)이 필요해요. 그래서 엔진 동작은 넉넉하고 범용적으로 만들고 자주 바꾸지 않아요.
- 사이트의 화면 구조(선택자)에 기대는 커넥터는 사이트 개편 때 깨져요. 카나리와 "브라우저 도구로 이어 하기"로 받쳐요.
- 정해진 동작만으로 표현하기 어려운 흐름(달력·복잡한 선택)은 커넥터가 화면까지 데려간 뒤 브라우저 도구로 넘겨요(`handoff_to_agent` 단계). 이런 곳이 많아지면 엔진 동작을 더할지 다시 봐요.

## 고친 내용 (2026-11-17)

- **사이트 API를 직접 부르지 않는다.** 처음에는 그 사이트 탭 안에서 사이트의 데이터 요청을 두리가 만들어 보내는 `fetch`를 두었지만, 사람이 하지 않는 방식으로 사이트 서버에 요청을 보내는 일이라 없앴어요. 이제 커넥터는 사람처럼 **주소를 열고 화면을 읽어요**.
  - 화면 선택자가 불안한 사이트는 **그 화면이 스스로 받은 응답**을 읽어요(`capture`, 확장이 탭의 응답을 듣기만 함). 서버가 결과를 화면과 함께 보내는 사이트는 화면에 박힌 데이터를 읽어요(`embedded`).
  - 같은 검색이라도 화면을 끝까지 그리는 만큼 조금 느려져요(캐치테이블 검색 2.1초 → 11.4초). 대신 사이트가 보는 동작은 사람이 그 화면을 연 것과 같아요.
- 사이트가 바뀌어 커넥터가 깨지는 것은 [ADR 0020](0020-connector-health.md)의 감시 파이프라인으로 빨리 잡아요.
